# DropBeam release-readiness audit — 2026-10-04

Branch `ios` @ aa2629d (build 0.52.13). Six parallel read-only audits: transfer engine, folder sync/Locations, desktop UI, iOS/App Store, chat/friends/accounts/Transfer Server, publishing/platforms. All findings traced in code; none live-tested unless noted.
North star: appliance-grade — "plug in a box and it always works", zero silent data loss, secure by default.

Health: `cargo test --lib` 457 pass / 1 timing flake (upload_limiter, passes alone); clippy 0 errors / ~250 warnings; `npm run build` ok (1.06 MB main chunk); eslint 34 errors (not in CI); rust-version 1.77.2 is wrong (code needs 1.89).

## Wave 1 — Security (P0)

- **S1 Device-link code = account takeover.** A `dropbeamlink1:` code pasted into Add Friend / Send "Have a code?" / popover / any QR scan / a `dropbeam://` URL on iOS runs `link.rs` `give()` with no confirmation → attacker gets account seed, all friends, 500 msgs/thread. `dropbeamjoin1:` moves the phone into attacker's account. Paths: FriendsView.tsx:538, store.ts openCode, App.tsx:276, Invite.swift:267, RootView.swift:120, Bridge.swift:200, nativeBridge.ts:77, SendView.swift:69, link.rs:253-360. Fix: device codes only from Settings→Devices + matching safety code on both screens; everything else describes the code first and asks.
- **S2 Strangers become auto-accept friends.** Any `friend-hello` → `upsert_with_id(auto_accept:true)` (friends.rs:539,757); `files` stranger guard bypassed by empty name (`None => (None,true)`, iroh_net.rs:2992-3007). Endpoint id is public (friend code, Quick Send ticket, invites). → files land in Downloads, chat notifications, any display name. Fix: inbound hello = pending request, auto_accept=false, refuse files/chat until accepted; non-friend pushes always prompt + size cap.
- **S3 Folder messages not bound to sender.** `folder-files`/`folder-ctrl`/`folder-reconcile` check only `has_pair` (iroh_net.rs:3638-4015); group link ids derivable by any member (pairing.rs:483). Viewer/ex-member can push files, tombstone everything, pause with epoch u64::MAX. Fix: require `conn.remote_id()==pair.endpoint_id` (key unkeyed link first), as `request_folder_snapshot` already does.
- **S4 Account device removal unenforced.** `server_exchange` merges roster before removed-check (account.rs:1120); removed/stolen device can re-link itself and send removal markers for others (apply_meta 741 → leave_account). Key never rotated. Fix: check first, require signatures from another device, rotate on removal.
- **S5 Contact hijack via invite id.** `apply_hello` re-points a keyed friend to any sender carrying its id (friends.rs:722); id is in every `dropbeamf1:` invite. Fix: only re-point unkeyed records; single-use invites.
- **S6 Spoofed link-preview cards.** Receiver never checks preview url/siteName vs the text link (link_preview.rs:366, ChatView.tsx:1316,1573). Fix: host must match; display host from URL.
- **S7 Downloads fingerprinting.** `files.verify`/`files.stat` hash/stat any name under Downloads for any friend (iroh_net.rs:2870-2918, 4516, 4566). Fix: per-sender delivered ledger; hash each path once.
- **S8 Unbounded incoming chat fields** (1 MiB frame only; iroh_net.rs:1277) + whole chats.json rewrite per msg. Fix: cap text 4000 / preview 160 / emoji 16; limit stranger threads.
- **S9 Push worker abusable** — public seal key, caller-chosen rate-limit keys, no per-IP/global cap (push-worker/worker.js:63-156); can burn KV quota → push dies for all. Diagnostics worker same + chunked bypasses size cap.
- **S10 Lab Mode fs-write/delete/move escape root** (`root.join(rel)` unchecked, lab.rs:283-317) and toggle is in shipping Settings. Fix: sanitize_rel + compile out of release.
- **S11 Block gaps**: `folder-files`/`folder-ctrl` not blockable (iroh_net.rs:2557); Transfer Server still pushes banners for blocked senders (mailbox/push.rs:427, NotificationService.swift:28).
- **S12 Tauri config**: `csp: null`, assetProtocol scope `**` (unused). Join code also accepts `link-offer` (link.rs:72). Display names not sanitized (bidi/zero-width; friends.rs clean_name).

## Wave 2 — Data loss / never-lose-a-file (P0/P1)

- **D1 "Delete after delivery" deletes undelivered files.** Receiver acks `ok` when nothing landed (paused, rename/copy failed, unplugged drive); unknown-pair/viewer bail → empty reply treated as Delivered (sync.rs:2622, iroh_net.rs:3663,3836,6740). Fix: explicit per-item result; empty ack ≠ delivered.
- **D2 Half-copied files sent then deleted/marked done.** `wait_until_stable` returns true on 25 s timeout; `seed_existing` has no stability check; signature taken post-send (sync.rs:2734,2778-2816,1306).
- **D3 History evicts bulk deletes** (500 items / 2 GiB cap per archive(); folder_history.rs:23,37,168) despite "Removed files are kept in History". Fix: never evict recent-N-days by cap; overflow to OS Trash + warn.
- **D4 Late delete beats newer edit; dir delete removes children deleter never saw** (apply_remote_delete sync.rs:3226 via :1984). Fix: version check vs tombstone ts; delete only listed children.
- **D5 Deletes made while app closed / watcher overflow resurrect** — no startup manifest-vs-disk diff (sync.rs:990, :566 ignores errors).
- **D6 Missing folder (unplugged drive) shows "Up to date" + endless full re-push** (sync.rs:613,2393,1519; FoldersView.tsx:194).
- **D7 Case-only rename loops forever between Macs** (case-sensitive keys; sync.rs:813,3814,2955,4019).
- **D8 Windows-illegal names (`a:b`, CON, trailing dot, `\`) loop + duplicate** (windows_safe_component iroh_net.rs:7228). Fix: per-pair original→landed map, or refuse + report.
- **D9 Location sync: same-size edits never upload; local always overwrites NAS ("newest wins" has no time compare)** (iroh_net.rs:4725, locations.rs:857, location_sync.rs:552). Deletes lost when host away (location_sync.rs:417).
- **D10 Location sync of a Shared Folder fails every pass** — top-level `.dropbeam-history`/`.DS_Store` not filtered (location_sync.rs:557,622).
- **D11 Messages acked before saved** (chat::save_all only logs errors, chat.rs:181) — server path deletes the only copy.
- **D12 Read receipts mark undelivered msgs read → never sent** (mark_read_up_to chat.rs:570; repro: link msg + 2nd msg within 8 s). Fix: receipts by id/seq; only promote delivered/held.
- **D13 Removing a group member doesn't stick** (others' beacons recreate link; commands.rs:899, pairing.rs:419).
- **D14 History restore mangles `:` names; unreadable index.json orphans all copies** (folder_history.rs:143,187).
- **D15 Windows: moved-in old file older than a tombstone gets auto-deleted** (ctime 0; meta_version_ms sync.rs:3075).
- **D16 Pause breaks under clock skew** (epoch = wall clock, needs >= stored; pairing.rs:731).
- **D17 Own-device chat sync whole-record LWW by wall clock** loses concurrent reactions/edits (chat.rs:881); clock skew can undo friend removal (account.rs:379,812); stale window's settings save reverts synced name (commands.rs:86).
- **D18 Desktop: slow first getSettings (>9 s) → defaults can overwrite real settings** (store.ts:620-627, saveSettings ~1003).

## Wave 3 — Always gets through (transfers, P1)

- **T1 Folder sends of ~5k–15k+ files always fail** — full chatTransfer manifest in every push header > 1 MiB cap (iroh_net.rs:4852,9171,2604,7309); Quick Send same (:9940,9989,4275). Tests stop at 1,500 files.
- **T2 Big single files on LAN not resumable (regression 540a837)** — `parallel_streams_for` returns 0 on local path; resume requires >0 (iroh_net.rs:7642,8771,3114,5296). Fix: return 1.
- **T3 Windows can't receive to FAT32/exFAT** — publish uses hard_link only (locations.rs:370). Fix: MoveFileExW no-replace, hard_link fallback.
- **T4 Headless `--server` refuses all Location uploads** — headless refusal arm precedes location arm (iroh_net.rs:2921; clippy "unreachable pattern").
- **T5 iOS verify/resume look in Downloads instead of Documents** (iroh_net.rs:2880,2898).
- **T6 Cancel shows as "Failed: connection lost" on the other side** (noq error Display drops reason; `to_string().contains("canceled")` everywhere). Fix: `{e:#}`/downcast + explicit cancel frame.
- **T7 Windows duplicate detection broken** — mandatory lock on stage file blocks `identical_landed` re-open (receive_stage.rs:96, iroh_net.rs:9038) → "name (1)" copies.
- **T8 iOS transfers die on background** — no beginBackgroundTask / BGContinuedProcessingTask; no network_change() on foreground.
- **T9 iOS LAN discovery likely dead on device** — swarm-discovery raw multicast needs `com.apple.developer.networking.multicast` (medium confidence; check device log for `mDNS: discovered`). Alt: NWBrowser → feed addrs.
- **T10 Production depends on n0 public canary relays/DNS** (iroh_net.rs:2346 presets::N0; pkarr publish failures in Linux logs). Ship own default relay. (Feeds the box/relay product.)
- **T11 Transfer Server**: partial `mailbox-in/*.ct` + `.dropbeam-mbx-*.part` never cleaned; cancelled uploads hold quota 7 days, cancel sent once; resume after blip → "busy"; startup read error deletes held items; blocking IO under global lock (hung NAS freezes app); chat queued behind big file; dup completed card; late-changed file → permanent "refused"; mtime lost; removed device can still fetch; server holds own chats for non-members; unsend fails if one device fetched (client.rs/server.rs refs in agent notes).
- **T12 Fanout**: re-send of same paths within 24 h skips devices that already got old version (fanout.rs:1124); cancelled legs requeued after quit (:749,833).
- **T13 Quick Send links never expire**, list re-gathered at pull time, two pullers kick each other (iroh_net.rs:66,4186,2711).
- **T14 Perf**: progress events clone full manifest 5×/s (:673); `partial-dirs.json` grows forever + swept hourly (:7363,7950); O(n²) queue `iter().any` under std Mutex blocking tokio (sync.rs:2807,2138,820); 100 notification dings per 3,000-photo sync (sync.rs:2213); iOS bridge re-serializes all snapshots per store change, decoded on main thread.
- **T15 Speed/ETA wrong**: chat-card speed counts earlier pushes/resume offset → GB/s (iroh_net.rs:1066); desktop ETA "calculating…" forever + disagrees with chat (store.ts:1126, TransferCard.tsx:96).
- **T16 Raw technical errors** reach users (friendly_failure only maps disk-full; ~90 `String(e)` toasts in UI). FAT32 4 GB limit hit only after 4 GB sent.
- Smaller: receiver cancel leaves 7-day hidden partial; watchdog marks Failed while bytes still land; Windows reserved names incomplete (COM¹ etc.); `mtime==0` matches any; panic log never pruned; headless lock waits forever, Windows `--server` uses XDG paths.
